## Description

A data model of Netflix: members and their profiles, devices, subscription plans with per-country prices,
payments in local currencies, the title catalog (movies, series, seasons, episodes, genres, cast) and viewing activity
(watch sessions and ratings).

- **Diagrams**: conceptual model (Chen), logical model (Crow's Foot, 21 entities, 110 attributes, 3 many-to-many
  relationships) and a data warehouse (UML, 3 fact tables, 7 dimensions).
- **Database** (SQL Server) in three layers:
  `stg` (raw CSV batches) → `core` (normalised model, business rules enforced) → `dw` (star schema for reporting).
- **Data**: 2023-01-01 → 2026-10-26. The **titles are real** (Netflix *What We Watched* engagement reports,
  enriched from TMDB) and their popularity follows Netflix's published hours viewed. **Members, subscriptions,
  payments and viewing are synthetic**, generated by a deterministic simulation. Exchange rates are real (ECB).
- **Live load demo**: the history is loaded up to 2026-10-18; each day from 2026-10-19 to 2026-10-26 can then be
  loaded on its own (≈3 s) and appears in the report after a refresh.

## Brand-new run

Commands are run from the `course-work/Implementations` folder. The server name `.\SQLEXPRESS` is the default
instance name of SQL Server Express - replace it if yours differs.

**1. Clone the repository** (the fork) and open a terminal in `course-work/Implementations`.

**2. Generate the data** (≈1 minute, offline, no API key needed):

```bash
py -3 data/generator/simulate.py
```

This creates `data/batches/history/2023-01 … 2026-10` (monthly, up to 2026-10-18) and
`data/batches/daily/2026-10-19 … 2026-10-26` (one folder per day). The seed is fixed, so the data is the same on
every run (with a different numpy version the random draws may differ slightly - the data stays valid).

**3. Point the load scripts at your data folder.** In `sql/09_load_history.sql` and `sql/10_load_day.sql`, set
`@DataRoot` to the full path of your `data\batches` folder.

**4. Create the database and load the history** - run the scripts in order:

```bash
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/01_create_database.sql
```
```bash
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/02_core_tables.sql
```
```bash

```
```bash
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/04_dw_tables.sql
```
```bash
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/05_functions.sql
```
```bash

```

```bash
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/09_load_history.sql
```

(or open each file in SSMS and execute it). Step 09 takes ≈6–7 minutes and ends with
`History loaded in … s`. Expected result: ≈1,130 accounts, ≈1.21 M watch sessions, ≈29.5 k payments,
data up to 2026-10-18.

> **If `BULK INSERT` fails with "access is denied" (error 4861)**: the SQL Server service account cannot read the
> folder. Grant it read access (run in a terminal, adjust the path):
> `icacls "<path>\data\batches" /grant "NT Service\MSSQL$SQLEXPRESS:(OI)(CI)R" /T`

**5. Live load demo** - set `@Day` in `sql/10_load_day.sql` (2026-10-19 … 2026-10-26) and run it:

```bash
sqlcmd -S ".\SQLEXPRESS" -E -C -b -i sql/10_load_day.sql
```

It prints the rows staged, inserted/updated in core and in the warehouse, and the new `DataAsOf` date. Running the
same day twice is safe - nothing is loaded twice. Refresh the Power BI report to see the new day.

**6. Power BI** - open the report and connect to server `.\SQLEXPRESS`, database `NetflixDB`, schema `dw`.

**Start over**: run step 4 again starting from `02_core_tables.sql` (02 and 04 drop and recreate their tables, so all data
is reloaded from the batches).

## How the load works

```
CSV batch folder ──stg.usp_ImportBatch──► stg  (BULK INSERT, 14 files)
                 ──core.usp_LoadFromStaging──► core (business keys -> IDs, rules checked)
                 ──dw.usp_LoadWarehouse──► dw   (dimensions type 1, facts incremental)
```

- Each procedure runs as one transaction: a batch either loads completely or not at all, with a clear error message.
- Loads are idempotent: rows are matched on business keys (e-mail, GUIDs, source keys), so re-running a batch adds nothing.
- Rules that constraints cannot express are enforced by the triggers (maturity limit, episode/title and device/account
  consistency, no overlapping subscriptions) and by the load procedure (viewing only during an active subscription).

## Data sources

- Netflix, *What We Watched: A Netflix Engagement Report*, H1 2023 – H1 2026 (titles, release dates, hours viewed).
- TMDB API (genres, maturity ratings, cast, seasons, episodes).
  *This product uses the TMDB API but is not endorsed or certified by TMDB.*
- European Central Bank euro reference rates (converted to USD; days without a published rate carry the last rate forward).
- Plan prices (`sql/08_reference_data.sql`): real price history for the US, Bulgaria and India; one approximate price
  level for the other countries.

Rebuilding `catalog.json` from the sources is optional and needs internet access and a TMDB read access token:

```bash
py -3 data/generator/build_catalog.py --token-file <path-to-token-file>
```
